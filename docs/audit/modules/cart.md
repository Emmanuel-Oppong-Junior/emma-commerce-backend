# Cart
Verdict: REWRITE (cart-line identity and pricing model; the module is ~170 lines, so the rewrite is small)
Reviewed by: Customer-Features reviewer, Claude Sonnet 5.5, default effort
Files reviewed: `src/cart/**` (resolver, service, repository, dto/, entities/, module, 3 specs), `src/discount/discount.service.ts` (`applyDiscountsToCart`), `src/order/order.service.ts` (price and stock use at checkout, read only to cross-check), `src/order/order.resolver.ts` (`finalizeOrder`), `prisma/schema.prisma` (Cart, CartItem, Product, Variant), `FRONTEND_API_DOCUMENTATION.md` (cart note), `docs/audit/modules/variant.md` (cross-ref), `test/e2e/cart.e2e-spec.ts` (names).

## Summary
Authorization is sound: every operation resolves the cart from the token's user id and item ids are checked against that cart's items, so one user cannot touch another's cart. The model, however, is product-only: there is no `variantId` in the add input, a cart line is identified by `productId` with no uniqueness at the database, the price stored on the line is captured once and then drifts, and only `isActive` and raw `Product.quantity` are checked (DRAFT/ARCHIVED, `stockStatus`, `expiryDate` are ignored). Two concurrent adds create duplicate lines. The `cart` query returns null totals, so the client must use a second query (`cartWithDiscount`) whose numbers the checkout does not honour.

## Positives (checked, no defect)
- Object-level authz: `updateCartItem` and `removeFromCart` look the item up inside the caller's own cart (`cart.items.find`) before acting, so passing another user's `cartItemId` yields NotFound.
- `addToCart` rejects inactive products, non-existent products and quantity above current stock (including the existing line quantity).
- Cart and lines cascade-delete with the user.

## Test assessment
Unit specs (resolver 264, service 229, repository 208 lines) all pass. They assert mock calls rather than persisted outcomes. No test exercises concurrency, schema uniqueness, variant handling, draft/archived products, or the cart-vs-order price relationship.

## Definition of done to close this module
1. New line identity `(cartId, productId, variantId)` with a DB uniqueness rule and atomic increment; cart creation via upsert (CART-01/03/04).
2. Variant support wired into price and stock (coordinate with Variant/Order reviewers).
3. One server-side pricing function shared by the cart view and checkout; cart line stores no drifting price; cart query returns totals and availability (CART-02/06/07/08).
4. Single purchasability rule (published, active, not expired, stockStatus) used by cart and checkout (CART-05).
5. Product/variant delete behaviour defined (CART-09); per-line quantity cap config (CART-10).
6. DB-backed tests for the items above (CART-12).
