## Summary
Tax is not computed at checkout at all. It is baked into `Product.price` when a product is written: `price = basePrice × (1 + Σ active Tax.rate)`, and a create/update/delete of any `Tax` row re-prices every taxable product with one raw SQL `UPDATE`. Orders store no tax amount, rate or breakdown, so VAT and levies can't be reported or invoiced. The model sums rates and has a single boolean `isTaxable`, so it can't express compounded levies, exemptions/zero-rating by category, or effective dates. Two defects corrupt prices today. (1) `UpdateProductInput.isTaxable` defaults to `false` in the GraphQL schema, so any product edit that omits it strips tax from the price, and for products without `basePrice` (all seeded products) sets the price to 0.00. (2) The re-price SQL multiplies `numeric` by a JS float parameter and calls `ROUND(…, 2)`, which very likely fails in Postgres after the tax row is already saved.

## Test assessment
- `npx jest src/tax` → `tax.repository.spec.ts` passes (mocked; asserts `getTotalActiveRate` sums 0.15 + 0.025 ≈ 0.175).
- No test exercises `TaxService`, the raw SQL, or product price computation. TAX-02 needs a DB-backed repro; TAX-01 can be reproduced with an e2e `updateProduct` call omitting `isTaxable`.

## Definition of done to close this module
1. Tax computed at checkout from net (pre-tax) unit prices using tax codes/classes and ordered/compoundable rules with effective dates; shipping taxability explicit.
2. Per-line and per-order tax snapshot persisted (amount, rate, base, tax code) and shown on order/receipt.
3. No more mass re-pricing via raw SQL, or if kept, Decimal parameters, one transaction, audit entry.
4. `UpdateProductInput` no longer injects `isTaxable = false`; null `basePrice` cannot produce a 0.00 price.
5. One Decimal rounding function; documented rule (per line, half-up, 2 dp).
6. Tests: re-price integration test, update-without-isTaxable regression, compounding example, rounding examples (10.10 @ 15%).
7. Docs and stale test helpers updated.
