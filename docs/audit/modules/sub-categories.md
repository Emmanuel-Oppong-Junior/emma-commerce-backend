# Sub-categories
Verdict: **NEEDS WORK**
Reviewed by: Catalogue reviewer A, Claude Sonnet 5.5, default effort
Files reviewed: `src/sub-categories/**` (service, repository, resolver, module, dto/, entities/, 3 specs), `src/products/products.service.ts` (subcategory use), `schema.gql` (`SubCategory` type), `prisma/schema.prisma` (SubCategory, Product), `prisma/migrations/*first_migration*` (FKs), `src/iam/authentication/guards/roles.guard.ts`, `test/e2e/sub-category.e2e-spec.ts` (test names).

## Summary
Create is guarded and unique per (name, category), but: the GraphQL `category` field is typed as `SubCategory` (wrong type in the public schema), update/delete are restricted to ADMIN only and exclude SUPER_ADMIN, the list/detail queries need a login so guests cannot build a category menu, `categoryId` is never checked for existence on create/update (unmapped FK error), and a sub-category can be moved to another category while products still carry the old `categoryId`.

## Test assessment
Resolver spec calls methods directly, so decorators (role metadata) are never exercised; only e2e could catch SUB-02 and it has no SUPER_ADMIN case. No test validates the schema shape of `SubCategory.category`.

## Definition of done to close this module
1. `SubCategory.category` typed as `Category` (SUB-01) with a schema snapshot or e2e query test.
2. Update/delete allowed for ADMIN and SUPER_ADMIN, with a role-matrix e2e test (SUB-02).
3. Public read queries for guests, filterable by category (SUB-03).
4. Category existence validated, FK/not-found errors mapped, and moving a populated sub-category either prevented or consistently migrated (SUB-04/05).
5. Name validation and case-insensitive uniqueness aligned with the decision for categories (SUB-06), plus tests (SUB-07).
