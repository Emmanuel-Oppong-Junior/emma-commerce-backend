## Summary
`CurrencyService` is unused: no provider injects it, so no amount anywhere is ever converted, for display or for charging. Its hard-coded rates, float math and silent fallback to rate 1 would be dangerous if it were wired in. The real currency risks are elsewhere. `Product.currency` is admin-settable per product, but checkout sums all prices as if they were GHS. The Paystack charge currency is taken from the client request body and sent with a GHS-denominated amount, and payment verification never checks the paid amount or currency. The system should be single-currency GHS with currency fixed server-side, until a proper multi-currency design (price lists or converted display only, GHS settlement) exists.

## Test assessment
No tests exist for `CurrencyService`. No test asserts the currency sent to Paystack or checks verified amount/currency.

## Definition of done to close this module
1. Currency is a server-side decision: GHS for every order and payment; client input ignored or rejected.
2. Payment verification and webhook require amount and currency to match the order before marking paid (shared with the payment module).
3. `Product.currency` removed or constrained to GHS until a price-list design exists; `Order.currency` stored.
4. `CurrencyService` deleted, or rebuilt as display-only with a dated rate source, Decimal math, explicit failure on unknown codes, and tests.
5. Docs updated.
