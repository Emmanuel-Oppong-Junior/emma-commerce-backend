## Summary
CRUD, SKU/category validation, admin role checks and DataLoaders for variants/reviews/discounts are in place and read cleanly. The weak points are (1) **anonymous access**: any visitor can reach reviewer PII and order history through `product.reviews.user`, and can read DRAFT/ARCHIVED/inactive products by id or by `isActive:false`; (2) **stock integrity**: `quantity` is an absolute, un-logged, admin-writable field that is overwritten on every product edit and never reconciled with variants, `stockStatus` or expiry; (3) **filters/search/pagination** contain real bugs (`inStock` is a no-op, price range clobbered, `subCategoryName` compares the wrong variable, raw text goes into `to_tsquery`). The three products spec files do not compile (stale against the current DTOs), so the module has no working automated tests; categories/variant/subcategory specs pass but only assert mock calls.

Baseline reason for failing suites (`tmp/audit/baseline/jest.txt`, `tsc.txt`): `products.service.spec.ts` and `products.resolver.spec.ts` build inputs with `price`, but `CreateProductInput` now takes `basePrice` + `isTaxable` (TS2345/TS2353); `products.service.spec.ts:158` passes `{id:true,name:true}` as `ProductSortArgs`; `products.repository.spec.ts:199` calls `findMany` with 2 args (signature now takes 3-4) and `:210` passes `true` where `SortOrder` is required. The tax/price refactor changed the code; specs were not updated. They fail at TS compile (ts-jest), not at runtime.

## Definition of done to close this module
1. PRD-01 fixed and covered by an e2e test (anonymous cannot read `reviews{user{email}}` or `user{orders}`).
2. Public product queries enforce `isActive && status=PUBLISHED && not expired` server-side; admin has a separate list query (PRD-02, PRD-04).
3. Stock changes only through audited, atomic paths; `quantity`/`stockStatus` removed from `UpdateProductInput`; initial stock logged (PRD-03, PRD-07).
4. Filters fixed (`inStock`, price range, tags, `subCategoryName`), search sanitised and indexed, pagination has an `id` tie-breaker (PRD-05/06/09/10).
5. Selection builder replaced/hardened (fragments, ordering) and depth/complexity limits added (PRD-12/13).
6. DTO validation tightened for price/quantity/nulls/brand/URLs; category/subcategory consistency checked against existing state (PRD-14/15).
7. P2002/P2003 mapped globally; hard delete forbidden or checks variants and no longer cascades audit data (PRD-16).
8. Reviews loader excludes soft-deleted reviews and is bounded (PRD-17).
9. All three products specs repaired and extended with behavioural tests for the above; docs updated (PRD-23/24).
