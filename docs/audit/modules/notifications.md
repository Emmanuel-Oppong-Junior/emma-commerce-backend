# Notifications
Verdict: REWRITE (small module, ~150 lines; the fire-and-forget email-only design cannot support reliable receipts, SMS/WhatsApp or retries)
Reviewed by: Customer-Features reviewer, Claude Sonnet 5.5, default effort
Files reviewed: `src/notifications/**` (service, module, `email/email.service.ts`, `email/templates/email.templates.ts`), all callers (`src/iam/authentication/authentication.service.ts`, `src/order/order.service.ts`), `src/config/env.validation.ts`, `src/main.ts`, `node_modules/resend` type definitions (v6.10.0), `src/iam/authentication/dto/sign-up.input.ts`, `FRONTEND_API_DOCUMENTATION.md` section 15. The working tree has uncommitted edits to `email.service.ts` and `email.templates.ts` (git status); the current working-tree content was reviewed.

## Summary
Five emails exist (welcome, order confirmation, shipped/delivered, payment confirmation, password reset) sent through Resend with `void` fire-and-forget calls, so requests are not blocked. Problems: Resend returns `{ data, error }` rather than throwing, and the code ignores `error`, so quota/domain/validation failures are logged as "Email sent"; the payment-confirmation email is never triggered; templates interpolate unescaped user-controlled strings; one caller chain has no `.catch` and can crash the process; there is no retry, queue or outbox, and no SMS or WhatsApp channel, which matters for a Ghana-first shop. The module has no tests.

## Test assessment
None. No unit or integration test for the module; the e2e suites do not assert emails.

## Definition of done to close this module
1. Provider result handled correctly: `error` checked, failures logged accurately and surfaced (NOT-01).
2. Outbox + worker with retries and delivery status; no `void` sends on the request path; all fire-and-forget callers have `.catch` (NOT-02/03).
3. Channel abstraction with SMS and WhatsApp for Ghana-critical events and phone verification (NOT-04).
4. Payment confirmation wired to the payment success transition; shipping/delivered/cancelled emails sent once per transition with correct templates (NOT-05/06).
5. Escaped, branded, GHS-formatted templates with `orderNumber`; reset link flow (NOT-07/08/10).
6. Production config fail-fast for provider and sender (NOT-09); unit tests for the above (NOT-11).
