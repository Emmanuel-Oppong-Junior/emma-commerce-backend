# Returns
Verdict: REWRITE
Reviewed by: Order, Inventory & Payment reviewer, Claude Opus 5.5, high
Files reviewed: `src/returns/**` (service, repository, resolver, module, dto, entities, enums, specs), callers in `src/order/order.service.ts:446-455`, `prisma/schema.prisma` (ReturnRequest, Payment, OrderItem), `test/e2e/payment-return.e2e-spec.ts` (return section), `FRONTEND_API_DOCUMENTATION.md:1600-1660`, `2770-2830`.

## Summary
A return is a whole-order request with free-text reason. It has no items, no quantities, no window, no "goods received" step and no link to a refund record. Ownership and the DELIVERED precondition are checked correctly. The refund step calls Paystack `/refund` and then, in a separate transaction, marks the request REFUNDED and puts **every item of the order** back into sellable stock. This happens even when the order was cancelled before shipping and its stock was already restored. The Paystack call isn't idempotent, so a double-click or a DB failure after the call refunds twice. Refund amounts are unbounded, refunds are marked done when merely initiated, and COD orders can't be refunded at all. The model can't support partial returns, exchanges, inspection or MoMo refunds, so it needs replacing, not patching.

## Test assessment
`returns.service.spec.ts` and `returns.repository.spec.ts` pass. They cover the happy path and simple guards with Prisma and axios mocked. Nothing covers the cancel → refund double restock, concurrent refunds, DB failure after a Paystack success, over-refund, or COD. The e2e tests cover create/duplicate/not-delivered only.

## Definition of done to close this module
1. `ReturnRequest` → `ReturnItem` (orderItemId, qty, reason, condition). Window and returnable policy per category, based on `deliveredAt`.
2. Flow: REQUESTED → APPROVED → (goods RECEIVED/INSPECTED → restock resaleable qty, logged) → REFUND_PENDING → REFUNDED/REFUND_FAILED, each a conditional transition.
3. `Refund` entity (amount ≤ refundable remainder, method: Paystack/MoMo transfer/manual, provider id, status) with an idempotency key. Driven by Paystack refund webhooks. Updates Payment status.
4. Cancellation of a paid, unshipped order triggers an automatic idempotent refund and never a second restock.
5. Tests for every transition, including concurrency and partial failure.
