# Shipping Zones
Verdict: REWRITE
Reviewed by: Catalogue reviewer B, Sonnet 5.5, default effort
Files reviewed: src/shipping-zones/** (no spec files exist), src/order/order.service.ts (fee lookup), AddressesService usage, prisma/schema.prisma (ShippingZone, Address, Order), order.service.spec.ts

## Summary
Fee lookup path: `OrderService.createDeliveryOrder` -> `ShippingZonesService.getFeeForCity(address.city)` -> `findFirst({isActive, cities has lower(trim(city))})`. The `getShippingFee` query uses the same function via the user's saved address. If no zone matches, the fee silently becomes 0 (free delivery). City overlap is not prevented and `findFirst` has no ordering, so which fee wins is undefined. The order stores no shipping fee or zone. Admin CRUD is correctly guarded. The flat city-string-array model cannot express Ghana delivery pricing, so a redesign is recommended rather than patching.

## Definition of done to close this module
- No zero-fee fallback; undeliverable addresses rejected (SHZ-01).
- One zone per city, deterministic lookup, country-aware (SHZ-02, 04, 05).
- Shipping fee and zone snapshot stored on Order (SHZ-03).
- Rate model extended for Ghana needs (SHZ-06): regions, weight/threshold, methods, COD.
- Input/update hardening (SHZ-07); unit + e2e tests (SHZ-08); docs (SHZ-11).
