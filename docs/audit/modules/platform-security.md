# Platform security (bootstrap, GraphQL config, error handling, throttling, env config)
Verdict: NEEDS WORK
Reviewed by: IAM & Security reviewer, Claude Opus 5.5, high
Files reviewed: `src/main.ts`, `src/app.module.ts` (ThrottlerModule, GraphQLModule, global providers), `src/commons/filters/all-exceptions.filter.ts`, `src/commons/error-formatters/grapqhl-error.formatter.ts`, `src/commons/guards/gql-throttler.guard.ts`, `src/commons/interceptors/graphql-logging.interceptor.ts`, `src/commons/middlewares/logger.middleware.ts`, `src/commons/useful-functions.ts` (sanitisers), `src/commons/logger.service.ts`, `src/config/env.validation.ts`, `src/config/cache.config.ts`, `.env.example` (keys only), `node_modules/@nestjs/throttler@6.5.0`, `@nestjs/core` router context, `@nestjs/graphql` resolver explorer.

## Summary
Helmet (CSP + HSTS in production), an explicit CORS allowlist that is mandatory in production, strict `ValidationPipe`, introspection off in production and production error masking are all in place. The custom `GqlThrottlerGuard` correctly turns the v6 "every named throttler applies to every route" default into opt-in. But one global interceptor written for GraphQL breaks every REST endpoint (Paystack webhook, payment initialisation, uploads, health), credentials are written to logs, the GraphQL server has no depth/complexity limits on a cyclic schema, rate limiting is in-memory and depends on a hard-coded `trust proxy` hop count, and the environment fails open when `NODE_ENV` is unset.

## Test assessment
No tests for `GqlThrottlerGuard`, `AllExceptionsFilter`, `formatError`, `GraphqlLoggingInterceptor` or `sanitizeVariables`. `logger.middleware.spec.ts` and `logger.service.spec.ts` pass. The e2e suite that would have caught PLAT-01 is not runnable (baseline: no `.env.test`, broken `db.helper.ts`).

## Definition of done to close this module
1. PLAT-01 fixed; e2e smoke for every REST route through the real `AppModule` in CI.
2. PLAT-02: no token/password values in logs (unit test over all auth DTO keys); existing logs purged.
3. Redis-backed throttling in production, per-email limits for auth flows, `TRUST_PROXY` configured and verified per environment.
4. Depth + complexity limits with tests that a deep/cyclic query is rejected.
5. Correct error codes per HTTP status.
6. Env validation rejects placeholders, enforces distinct secrets, requires explicit `NODE_ENV`; `.env.example` complete.
